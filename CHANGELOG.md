# Changelog

## v3.8.0 — 2026-10-XX

**Platform:** Windows (.NET 10 / WPF). Widgets come to the Desk: signed packs from the 626 Labs catalog, a companion that grows with the days you code, and widgets Claude Code makes with you that install only on Apply. Updates restart on your click. This is the Microsoft Store release: the Store was on 3.7.1, and 3.7.2 shipped on GitHub only, so the Store update carries 3.7.2's fixes too. `Sanduhr.Mcp` to 3.8.0. **One new outbound destination**, GitHub releases of `626Labs-LLC/sanduhr-widgets`, reached only when you open Settings ▸ Widgets or install a pack (PRIVACY has the hosts). No new capability; the manifest still declares `runFullTrust` only and changes only its version.

### Widgets

- **Settings ▸ Widgets** (in the Desk group) lists the widget catalog and the packs you have, with Install, Update and Uninstall. The first packs are the hourglass sprite and the OLED Neon theme, palettes and effects. Themes, palettes, effects and fonts from packs join the lists you already pick from.
- **The catalog is signed and every pack is checked again on your PC.** Sanduhr verifies the catalog's ECDSA P-256 signature against a key built into the app before it reads a byte of it, refuses an older catalog served back, checks each zip's size and SHA-256 against the catalog, reads the zip without inflating anything, and runs the whole pack through `PackValidator` before it is renamed into `%LOCALAPPDATA%\Sanduhr\widgets\`. Packs are data only: JSON, PNG and fonts, never code.
- **Only when you ask.** The catalog is fetched when you open Settings ▸ Widgets or press **Check the catalog again**; a pack downloads only on Install or Update. Nothing polls in the background, and no account, cookie or identifier goes with the request (the user agent is just "Sanduhr"). Offline, or with a catalog that fails its check, the page says so and installs nothing.

### The companion

- **A new Desk piece, `companion`,** draws the sprite you pick in Settings ▸ Widgets: pixel art at whole-pixel scale, sitting at its anchor or, with **Let it roam**, walking the edges of its monitor. OLED care's drift and dim apply to it; with Windows' animations off it stays put and animates at 1 frame a second.
- **It grows with the days you code, never with your usage.** Growth reads Sanduhr Time's day files when they are there, otherwise the dates your local Claude Code logs show activity; the hourglass reaches its stages at about 3, 10 and 30 coding days and never goes backwards. Its mood follows your pace (content, focused, worried, exhausted at the limit), and it reacts to a watcher waiting on you or passing, an alert threshold, a reset and 20 minutes away.

### Widgets made with Claude

- **A new MCP tool, `propose_widget`.** Claude Code can design a pixel-art sprite (drawn as text: a palette of up to 16 colors and rows of characters, 8 to 32 pixels a side), palettes or effect presets in conversation. The server builds the pack, names it `my-<id>` so it can never replace a catalog pack, and checks it with the catalog's own rules, the trademark rule included, before anything is written. It never accepts a PNG, a font or code; a theme still goes through `propose_theme`.
- **It previews, then waits for Apply.** A sprite shows as the companion and a palette as the Desk ink, under a bar that says what the widget is and lists its files, with **Apply** and **Dismiss**. Nothing installs until Apply, and **Let Claude change the Desk directly** never covers a widget.
- **Use my own art…** on a sprite made here takes your own PNG sprite sheet per stage, checks it with the pack image rules, and checks the whole pack again. Your art stays on your PC; Claude never supplies an image.
- **The trust boundary, widened on purpose.** `sanduhr-mcp` now source-links 30 Core files (was 27): `PackJson`, `PackValidator` and `WidgetProposal`, all pure (bytes in, findings out). The pixel-sheet rasterizer stays in the app. Still no project or package reference and no network; `TrustBoundaryTests` pins the list and scans the new files for IO, network and process names.

### Restart to update

- **One offer, on your click.** When an update is ready, the toast, the tray and the widget say "Sanduhr 3.x is ready. Restart to update?" On yes, Sanduhr closes its WebView2 browsers and waits for them, then asks the Store to install (Windows shows its own dialog) or applies the downloaded update, and opens again on the new version. If the install fails or you cancel, Sanduhr keeps running and the offer stays. It replaces **Quit and update**.
- **Setup.exe installs update themselves from 3.8.** Before 3.8 the update check only noted a newer release in the log. Now it downloads the release in the background, at most once a day, and joins the same offer. A 3.7.x Setup.exe install needs this release's Setup.exe once.

### The Desk

- **The fold.** A Desk design from Claude Code can slant a stack of pieces from -20 to 20 degrees, plate included, so a left stack and a right stack read as two faces of a fold. Arrange Desk hit-tests, outlines and drags the slanted piece. Older layouts read and write unchanged.
- **Call the weather anything** (#315). Settings ▸ Weather ▸ **Show it as** puts a name of up to 24 characters ("Funky Town") on the weather piece in place of the city. The place search and the forecast never see it, and a Desk design can set it under the same review.
- **Livelier bars.** The bars beside now playing ease up and down, fall at a steady rate and wear peak caps that hold, then drop. **Gradient bars** (Settings ▸ Now playing, off by default) spreads your ink's colors across the row. Still the playing app's level only: no audio is captured.
- **Meter styles** (landing in 3.8, #336): one line here once the PR merges, or cut this bullet.

### Fixes

- **The usage connection rebuilds itself** (#331). When the WebView2 browser behind the widget exited, 3.7.1 showed "The WebView control is no longer valid" and never fetched again. Sanduhr now notices the exit, shows "Reconnecting…", and rebuilds the browser 5 seconds later (30 seconds after a failed try, then every 5 minutes); after two failed rebuilds the widget offers **Restart**.
- **From 3.7.2, for Store installs:** WebView2 no longer outlives Sanduhr and blocks the next update (0x80073D02); only one Sanduhr runs at a time; choosing a theme with a screen reader, voice access or the arrow keys applies it (#316); each Claude Code folder's controls and each Desk message line are named for screen readers; Now playing names a web app the way the Start menu does (#317); Launcher labels draw whole up to 24 characters (#318); the design review bar and Arrange Desk's bar open on the monitor the change is on (#319). Details under v3.7.2 below.

## v3.7.2 — 2026-10-22

**Platform:** Windows (.NET 10 / WPF). A patch on GitHub (Setup.exe) only; Store installs get these fixes in 3.8. `Sanduhr.Mcp` to 3.7.2: a Core file it already links gained a pure rule; the link list is unchanged. No new capability and no new outbound destination; the manifest still declares `runFullTrust` only.

### Fixes

- **WebView2 no longer outlives Sanduhr and blocks the next update (0x80073D02).** An `msedgewebview2.exe` left running after Quit kept the package in use, so installing an update failed until Windows restarted. Reproduced on a dev build: a second Sanduhr on the same data folder shared the first one's WebView2 browser, so ending the first left the browser running with its parent gone. Every browser process Sanduhr starts (the usage transport, each inactive account's check, the sign-in window) now sits in a job object that Windows ends with Sanduhr however it exits: Quit, a crash or End task. Quit hides the widget, closes every WebView2, waits up to 5 seconds for the browsers to exit by themselves, then ends any still running; no transport starts a browser once quitting has begun.
- **One Sanduhr at a time.** A second launch (two tray icons were seen once) now shows the running widget and exits. A launch while Sanduhr is still quitting waits for it and then starts, which is the restart after an update. A dev build's `SANDUHR_DEV_PROFILE` keeps its own claim, so it runs beside the installed app.
- **Choosing a theme through UI Automation applies it (#316).** The theme gallery in Settings ▸ Themes and the widget's quick switch are now lists whose items are named for their theme: selecting one with a click, the arrow keys or a screen reader's Select applies it, where before only a mouse click did.
- **Each folder's controls are named for the folder.** Settings ▸ Claude Code read "Linked account for this folder" on every row; the combo, **Forget** and the MCP check box now say which folder ("Linked account for ~\.claude-personal"). Settings ▸ Desk messages does the same per line ("Remove line 2", "Line 2 color").
- **Now playing names the app (#317).** Settings ▸ Now playing showed a web app's raw id ("Playing in Chrome._crx_cinhimbnk…") in the status line and the Apps list. It now shows the name your Start menu gives the app ("YouTube Music"), as the Launcher's app list does, and falls back to the id only when the Start menu doesn't list it.
- **Launcher labels draw whole up to their 24-character limit (#318).** Under its button a label was cut at about ten characters ("YouTube…"). A label now wraps to two lines, and when the longest one still needs room the buttons widen, up to 2.6 icons wide. A Launcher of short labels keeps its size.
- **The design review bar opens where the design is (#319).** With the Desk on a second monitor, **Apply** / **Dismiss** opened on the main monitor while the preview drew on the other. The bar now opens top center on the monitor that holds most of the pieces the design moves, the main monitor on a tie. Arrange Desk's **Done** / **Cancel** bar follows the pieces the same way.

## v3.7.1 — 2026-10-21

**Platform:** Windows (.NET 10 / WPF). Claude designs your Desk, the Desk gets a Launcher, every piece can live on its own monitor, every song can wear its own look, and the Desk learns to go easy on an OLED screen. ### The Desk, designed by Claude

- **Two new MCP tools, `get_desk` and `propose_desk`.** `get_desk` shows Claude how your Desk looks right now: where each piece sits and how big it is, the monitor it is on, the font, ink, plate and shadow, the Launcher's buttons, your widget theme's colors, the font families installed on this PC and the monitors connected. `propose_desk` hands the widget a whole look: layout, font, ink, plate, Launcher, messages, song looks and a widget theme, as many or as few of those as Claude changes. The server checks every field with the widget's own code first (shapes, ranges, the Launcher's targets, the ink's contrast against your wallpaper), so a design that fails is never written. Claude never runs anything: the request is a file in `%USERPROFILE%\.sanduhr`, and the widget answers in another.
- **Claude sees your wallpaper as numbers, and as a picture only if you allow it.** Sanduhr works out up to five dominant colors, the overall brightness, and the brightness and busyness behind each of the eight Desk anchors on each monitor, all on your PC. It also writes a copy of your wallpaper scaled to 1600 pixels as `wallpaper-preview.png`; Claude can open it only if you allow Claude Code to read that file. Nothing is uploaded by Sanduhr.
- **A live review on your real desktop.** A proposed look draws on the Desk and the widget, with a bar at the top of the main monitor: the design's name, Claude's note, what changed, then **Apply** or **Dismiss** (Enter and Escape work). Nothing is written until Apply, and Dismiss puts everything back at once. A font you don't have shows its download link (Sanduhr shows the link and never fetches it), and Apply waits until the font is installed.
- **Let Claude change the Desk directly** (Settings ▸ Desk, off by default) applies a proposal without the bar. The Desk it replaces is still saved first.
- **Saved designs, and Put my Desk back.** Every Apply saves the Desk it replaces. Settings ▸ Desk ▸ Designs keeps ten (the oldest unpinned goes first) and lets you Switch to, Rename, Pin or Delete one. **Put my Desk back**, in Settings and in the tray menu, returns to the look before the last change. Reset Sanduhr… removes the folder.
- **The trust boundary, widened on purpose.** `sanduhr-mcp` now source-links 27 Core files (was 17): the Desk design validator, the wallpaper summary, the piece, ink, plate, font and Launcher rules, and the song look rules. All of them are pure (text, JSON, regex, math). Still no project or package reference and no network; `TrustBoundaryTests` pins the list and scans the new files for IO, network and process names.

### The Launcher

- **Up to eight buttons on the Desk** that open an app or a web page when you click. Settings ▸ Desk ▸ Launcher picks apps from your Start menu, including Chrome and Edge web apps, desktop programs and programs installed on another drive, or takes an `https://` link. A button shows the app's own icon or a PNG you pick (resized on import to a 256 pixel square, never fetched from the web), glows in a color you choose on hover and touch, and is placed on the first button you add.
- **No command lines, ever.** A button opens only something your Start menu lists, through Windows' own app launcher, and checks that again at the click. No arguments, scripts, shortcuts or file paths. This is also why Claude can propose a Launcher without being able to run anything you didn't install.

### One Desk across many monitors

- **Each piece picks its monitor.** **All monitors**, **Main monitor** or one monitor by name, from the new **Monitor** dropdown in Settings ▸ Desk ▸ Where each piece sits. Arrange Desk gains **Show on** and lets you drag a piece from one monitor to another. When a monitor is unplugged its pieces move to the main monitor, and return when it reconnects; nothing is rewritten.

### A look per song

- **Style what's playing** (Settings ▸ Now playing ▸ Looks, off by default) draws the playing song in a gradient and a letter style, and the bars and the position bar take the gradient. A song with no saved look gets one seeded from its title and artist (eight palettes, five letter styles), so every song has a look the moment it plays.
- **A tool for Claude, `propose_now_playing_looks`.** Claude can suggest looks for up to 20 songs. They wait on Settings ▸ Now playing for **Save** or **Dismiss**, each drawn in its look, and a look too dim for the spot it sits in is refused. **Let Claude style songs directly** (off by default) saves them on arrival. **Clear Looks…** deletes every saved look.
- **Shared with the Claude Code now-playing mod.** While the MCP server is installed and Style what's playing is on, Sanduhr writes `now-playing-look.json` with a hash of the song and the look it wears (no title, no artist, no app), and reads `now-playing-look-offer.json` back from the mod, treated as a Claude proposal. The same song wears the same look on the Desk and in Claude Code.

### OLED care

- **Pixel drift, idle dim and no held pure white**, Settings ▸ Desk ▸ OLED care (off by default). The Desk and the widget move a few pixels in a slow figure-eight every 3 minutes, dim after 5 minutes without keyboard or mouse input, and draw pure white ink as a soft off-white (#e6e6e6). The only thing read is the time of the last input; not a key, a click, a program or a place.

### Fixes

- **Automatic ink and the wallpaper read follow the picture Windows still draws.** When the wallpaper's original file was deleted or moved, Sanduhr reads the copy Windows keeps (`TranscodedWallpaper`) instead of falling back to a default.
- **No crash when a theme change redrew a Settings calendar that was never laid out.**
- **The Designs rows are named for screen readers**, and their buttons are exposed to UI Automation.
- **Settings fixes.** Claude Code offers **Update…**, not Install, for a piece already in the folder, and the MCP install says which other folders keep their server and that account links don't change. Mods & Config opens on the folder Claude Code runs from, calls plugins plugins (with a small "mod" tag on the real mods and counts that add up), shows no "vunknown", and every list row in Settings reads out by name instead of by type.
- **A half-written offer from the now-playing mod is waited out** instead of dropped.

Cards live in memory only.

### Now playing

- **Shows only while something plays.** Now playing appears the moment a media app reports Playing and fades away 5 seconds after a pause or stop; resuming inside those 5 seconds never hides it. The rule reads the media session's own state, never the sound level, so a system chime can't open it. **Keep showing while paused** (Settings ▸ Now playing, off by default) replaces the old hide-while-paused switch. The widget's now-playing line follows the same rule.
- **No hole left behind.** When it hides, the other pieces in its stack slide to close the gap (about 0.6 s), and slide back as it returns (about 1 s), inside a Desk window that never resizes mid-move. With Windows animations off, it snaps.
- **The bars follow the music, not the dings.** The visualizer reads the playing app's own audio-session peak meter (Spotify, browsers, Media Player, Apple Music and more, matched by app), never the System Sounds session or Sanduhr's own chimes, and never the whole output device. Still peak values only, in memory, nothing captured.
- **Whichever app is playing wins.** With several media sessions open, a playing one beats a paused one that Windows calls current, so a paused browser tab can't hide your music.

### Claude Code

- **Five new MCP tools.** `watch_start`, `watch_update` and `watch_end` drive the Desk's watcher cards; `get_desk_messages` reads your Desk messages and `propose_desk_messages` suggests lines, which wait on Settings ▸ Message for **Add**, **Review** or **Dismiss**. Nothing changes your messages without Add. Requests travel as files in `%USERPROFILE%\.sanduhr`; the server stays network-free.
- **The trust boundary, widened on purpose.** `sanduhr-mcp` now source-links 17 Core files (was 11): the widget's own watcher and Desk-message validators, so the server refuses exactly what the widget would. Still no project or package reference; `TrustBoundaryTests` pins the list and reads the new files for IO, network and process names.
- **The statusline names its folder.** Sanduhr's line can start with an **Account** segment: the Claude Code folder's name (`.claude-personal` shows `personal`), or the `SANDUHR_LABEL` you set in that folder's own settings. Worked out when the line renders; Sanduhr stores no name anywhere, and `seats.json` still holds none. A plain `.claude` folder shows no label, and a segment list you picked before is kept exactly.

### Tour and Settings

- **The tour knows the Desk.** The full tour gains an **On your desktop** card whose Show me opens Settings ▸ Desk. Choosing **Just the Desk** opens a three-step Desk-only tour, and Take the tour… shows it while Just the Desk is on.
- **Quit from any Settings page.** **Quit Sanduhr** sits at the foot of the Settings sidebar, the same quit as the tray's. Search finds it as "quit", "exit" or "close".
- **The sidebar's search box and Quit are visible to screen readers**, along with the page list.

### Claude Code files move out of AppData

## v2.0.4-windows — 2026-04-19

**Platform:** Windows + macOS
**Feature release — advanced pacing, deep-work focus timer, cooldown snake game, hourglass physics tightening, and sign-out flow restoration.**

### Added

- **Always-on pace ghost.** A faint vertical tick on every tier card showing where pace says usage should be right now. Actual fill sits to the left (under pace), at (on pace), or to the right (ahead). Replaces the previous Projection graph mode + the bright `_pace_tick` widget that used to double-render at the same x-position. Ghost alpha tunable per theme via `ghost_alpha` (default 0.35, Matrix overrides brighter for CRT feel).
- **Horizon sparkline.** The pulse-histogram mode is replaced by a 4-band Heer/Tufte horizon chart — all bands render from the widget bottom with ascending alpha, so peaks pile up four-way overlap at the base and step down one band at a time as they reach the top. Denser information than a line chart, visually distinct enough that the graph-cycle button does real work. Cycle is now Classic / Horizon only.
- **Breathing glass.** Usage bars pulse with a 2.8s sine-wave alpha shimmer toward the theme's `accent` color, so the widget feels alive at rest. Amplitude 0.08 — subliminal, not flickery. Period tunable per theme via `breath_period_ms` (Matrix drops to 1800ms for a more CRT-alive cadence). 15fps timer, effectively free on CPU.
- **Edge-drag resize.** Hover any edge or corner of the frameless window → cursor changes → click-drag to resize. Minimum size dynamically computed from `QFontMetrics` of the longest user-facing strings (status messages, burn projections, tier labels) so text never clips. Resized geometry persists across launches via the `geom` key in `settings.json` (legacy `window` key migrated transparently on first save). Resize is disabled while the focus timer or snake overlay owns the window.
- **Advanced pacing tools.** Cards now surface **Cooldown required** (how long at zero usage to get back on pace) and **Surplus** (burn-rate delta when under pace) as deep-math metrics. Hover-to-reveal, not click, so you can glance and move on without stacking extra clicks.
- **Deep-work focus timer** (`⏳` in the tool strip). Replaces the tier cards with a 31×31 digitised hourglass overlay that drains in proportion to the remaining block. Inline minute-picker inside the overlay — no digging through Settings. Mac port renders via SwiftUI `Canvas` + `TimelineView`; Windows via `QPainter` + `QTimer`. Zero external dependencies on either platform.
- **Cooldown snake game** (`🐍` in the tool strip). A pure-Qt / pure-SwiftUI snake game for the wait state when you've blown through your budget and need to kill a few minutes. High score persists to `%APPDATA%\Sanduhr\settings.json` / macOS `UserDefaults`.
- **Graph-mode cycling** (`📊`). Cycles the tier-card graph between Classic / Projection / Pulse. `pacing.velocity_projection()` does the linear extrapolation for the Projection mode.
- **Tool strip** between content and footer. Consolidates Themes, Settings, Graph-mode, Compact, Focus, and Snake into persistent tooltip-bearing buttons with explicit `setAccessibleName` so screen readers — and MS Store review tooling — can identify every control by name, not by emoji glyph.
- **Sign out / clear credentials from the Credentials tab.** (Originally intended for v2.0.3 — see errata below.) Saving the Credentials form with an empty sessionKey triggers a confirmation dialog; confirming calls `credentials.clear()`, wipes `sessionKey` and `cf_clearance` from Windows Credential Manager, stops the fetcher, tears down tier cards, and sets the status to *"Signed out — paste sessionKey in Settings to resume."* Hint label under the sessionKey field advertises the behaviour so users discover it.

### Fixed

- **Hourglass sand-fall was drifting out of sync with wall-clock.** Two bugs in `focus._physics_tick`: (1) `elapsed` was derived from the integer-second `_remaining` counter, so the 30Hz physics tick had no sub-second resolution → sand stalled between 1Hz timer ticks and then dropped in clumps; (2) the bottleneck throttle only guarded the centre cell `(cy-1, cx)`, so diagonal falls from `(cy-1, cx±1)` into the bottom half bypassed the rate limit and the bottom half would outpace the timer over long focus blocks. Now uses `QElapsedTimer` for millisecond-resolution elapsed and throttles the entire `y == cy-1` row. Sand visibly drips in proportion to the fraction of the timer that's elapsed at all times.
- **Compact mode now actually shrinks the window.** Previously it only hid child widgets; the frame stayed the original size, wasting desktop space. Windows: `setFixedHeight(sizeHint.height())` after `adjustSize()`. Mac: SwiftUI `fixedSize` bounding.
- **Heartbeat pace marker is no longer clipped by the progress-bar container.** Moved from an inside-the-bar overlay to an absolute draw that protrudes a pixel above and below the bar, so it's visible at a glance regardless of fill level.

### Changed

- **Settings dialog tab order.** Themes first (quick win, low-stakes onboarding), Pacing + Help in the middle, Credentials last (the "spooky" one). Also dropped the `focus_minutes` option — the Focus overlay has its own inline minute-picker now — and replaced the *Auto-trigger snake* checkbox with a *Session 100% reminder* preference.

## v2.0.3-windows — 2026-04-17

**Platform:** Windows
**Patch release — Microsoft Store resubmission (light-mode dialog legibility).**

### Fixed

- **Dialogs unreadable on light-mode Windows.** Microsoft Store review (device: HP 17-bs011dx) caught the first-run welcome dialog and Settings dialog rendering as dark theme text on Windows' default *light* background — because the root stylesheet scoped its background to `SanduhrWidget` only, while cascading a light text color through `QWidget { color: ... }` to every widget including dialogs. On a light-mode host, the system filled the dialog background in white, producing light-on-white invisible text. Fix: explicit `QDialog`, `QMessageBox`, `QTabWidget`, `QTabBar`, `QLineEdit`, `QTextEdit`, `QListWidget`, `QDialogButtonBox`, and `QScrollBar` rules in the main stylesheet, all bound to the active theme's `bg` / `glass` / `text` / `border` / `accent` tokens. `_open_settings_dialog` now explicitly applies the root stylesheet to the dialog before `exec_()` — QDialog is a separate top-level window so it doesn't inherit QSS from its parent automatically. The `cf_clearance` help label in the Credentials tab no longer hardcodes its grey color (was invisible on Matrix theme and on light-mode Windows).

This was the root cause of the **10.1.4.4 App Quality / "Navigation of the product is poor"** finding in the last Store rejection. First-run setup is now legible regardless of the host system theme.

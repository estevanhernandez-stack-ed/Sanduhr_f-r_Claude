# Mac agent sources: design

Mac 2.46.0. Ports two Windows specs in one release (owner, 2026-11-19, decision `Y5SbjCXEbPIsVhuigpgy`):
the agent layer (`2026-11-09-agent-layer-design.md`, Windows 4.8: Codex limits beside Claude's) and every
agent's activity (`2026-11-13-every-agents-activity-design.md`, Windows 4.9: Codex and Antigravity CLI tokens
in the Vault). Those specs are the reference for behavior and wording; this one records only what the Mac does
differently and where each piece lands. Windows parity files: `windows-dotnet/src/Sanduhr.Core/`
`CodexLimitsReader.cs`, `CodexLimits.cs`, `CodexBurnSource.cs`, `AntigravityBurnSource.cs`,
`AgentBurnSource.cs`, `AgentBurnDeltas.cs`, `AgentSources.cs`, `SourceBar.cs`; `Sanduhr.App/Services/`
`ZstdRollouts.cs`, `CodexUsageService.cs`, `AntigravitySummaries.cs`. Read them, never edit them.

## The goal

Someone pacing more than one agent's plan sees every limit at once, and sees where their week went across
Claude Code, Codex and the Antigravity CLI, read from each agent's own files on this Mac.

**Success:** with Codex and the Antigravity CLI history on disk, switching both on in Settings ▸ Usage ▸ Sources
shows Codex's 5-hour and weekly limits under Claude's within a minute, and within two Vault ingests the Local
burn strip stacks all three agents. No sign-in, no network call on any agent's behalf, no prompt or reply read.

## Out of scope

Everything the Windows specs put out of scope (a live Codex fetch, `auth.json`, the Antigravity IDE, its
limits, the Gemini-app meter, local models), plus on the Mac:

- **Agent notifications** (Windows 5.0 spec 4). Their own Mac release.
- **Streamer mode.** The Mac has none, so Windows' codename rules have no Mac counterpart.
- **A real-data check gating the release.** This Mac has neither Codex nor the Antigravity CLI; the build and
  smoke run on made-up files (decision `xc0rewYY1FC8hU4SmYhu`). A real read happens when a Mac with Codex is
  at hand and is recorded in the smoke section.

## 1. Mac-specific decisions

- **zstd.** macOS has no system zstd and Apple's Compression does not decode it. Vendor zstd's official
  decompress-only single-file decoder (`zstddeclib.c`, generated by the zstd repo's own
  `build/single_file_libs/combine.sh` from a tagged release) as a C target `CZstd` in `Package.swift`
  (decision `LkT5L4NSc0Rh5IrV9h8m`). A Swift wrapper streams through `ZSTD_decompressStream` with Windows' 64 MB
  output cap. The licence goes in `THIRD-PARTY-NOTICES.txt` and the source's tag and SHA in a header comment.
  Fetching the source needs the owner's OK at that item.
- **Names.** `UsageSource` already means the Claude Code activity source on the Usage page, so the agent type is
  `AgentSource` (`claude`, `codex`, `antigravity`). Colors as Windows: Claude `#E0875A`, Codex `#2FB5A3`,
  Antigravity near `#7B8CF0`, each changeable, locked by a new `SourceContrastTests` against the 7 Mac
  built-ins and Match Desk using `ThemeLint.contrast`.
- **Codex homes.** `~/.codex`, plus `CODEX_HOME` only if the app's own environment has it. An app launched from
  the Dock does not see a shell's exports, so a `CODEX_HOME` set in `.zshrc` is missed; the Sources row says
  "Reads ~/.codex" so the rule is visible. Antigravity: `~/.gemini/antigravity-cli/` only.
- **SQLite.** The system `SQLite3` module (no package), opened `file:…?mode=ro` with a two-second busy timeout.
- **Change watch.** Codex limits poll every 30 seconds while Codex is on; no FSEvents stream (the poll reads
  newest files from their end, cheap, and keeps idle CPU under 1 percent: re-measure with cputime deltas).

## 3. Demo mode

Demo shows a sample Codex section when the Codex source is on, so screenshots can show the stacked widget and
combined bars; no agent rows in the Vault views and no footer pieces, as on Windows. Demo never reads
`~/.codex` or `~/.gemini`.

## 4. Privacy

Windows' section 5 holds word for word: what is read (Codex: timestamps, segment ids, `cwd`, model names, token
counts, rate-limit percents, window lengths, reset times; Antigravity: `conversation_id`, `workspace_uris`,
`created_at`, token counts), never prompts, replies, `title`, `preview`, `raw_summary` or `auth.json`. A test
pins the Antigravity SQL to exactly those two columns, another that no path to `auth.json` is ever opened.
`docs/PRIVACY.md` gains a Mac row for each. The MCP stays stdlib-only and network-free; this release adds a
Python test asserting it imports no network module, which the Mac lacks today.

## 5. Testing

Windows' testing sections, ported to Swift Testing with made-up rollouts (plain and `.zst`, compressed at
fixture-build time by the test itself through a checked-in `.zst` produced once) and a generated SQLite
database in a temp home. Injected roots everywhere (the reader takes a home URL; nothing reads the real
`~/.codex` in tests). Plus: one source on draws exactly today's widget (pinned), a layout word without the
source field reads Combined, `mcp-access.json` without `agents` reads both off, and the Python tests for the
statusline and MCP blocks.

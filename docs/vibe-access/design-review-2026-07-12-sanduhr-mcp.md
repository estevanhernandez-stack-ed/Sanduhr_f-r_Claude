# Design review: Sanduhr MCP server + snapshot seam

**Date:** 2026-07-12 · **Method:** five parallel adversarial lenses (security/privacy, correctness/staleness, agent-UX, packaging/distribution, vibe-access manifest) over the Tier-1 slate proposal in `docs/roadmap-2026-07-11.md`, grounded in the live codebase. **Verdict: sound-with-changes, 5/5 lenses.**

## What survives contact

The core shape is right and every lens independently confirmed it: **one writer (the widget's 5-minute fetch), one dumb-file rendezvous (`snapshot.json`), N read-only consumers (statusline script, `sanduhr-mcp.exe`), all derivations computed at read time.** Read-only stdio with ambient user authority is the correct auth model — any token on the MCP boundary would be theater, since a local process could read the file directly. Nothing proposed is seed/reset/capture-shaped. The opt-in consent gate is the right frame; it needs revocation teeth (below).

## The blocker — verify before any design work proceeds

**MSIX AppData write virtualization.** `Package.appxmanifest` declares `runFullTrust` only — no virtualization override. Packaged apps get copy-on-write redirection of `%APPDATA%` by default: the Store-installed widget's snapshot may land in the package's `LocalCache\Roaming` overlay while the statusline script (unpackaged, spawned by Claude Code) reads the *real* `%APPDATA%\Sanduhr` — feature dead on the Store channel, working on Velopack, invisible on dev builds. Local evidence is ambiguous (Store 3.1.0.0 installed, no `LocalCache\Roaming\Sanduhr`, but dev builds populate the real path — either reading is consistent).

**The spike (cheap, do first):** run the installed Store build, trigger a settings write, and check both the real path and `%LOCALAPPDATA%\Packages\626LabsLLC.SanduhrfrClaude_*\LocalCache\Roaming\Sanduhr`. If virtualized: either relocate the snapshot to a non-virtualized profile path (`~\.sanduhr\` — CC's own dotfolder is precedent, and virtualization covers AppData, not the profile root) or declare `FileSystemWriteVirtualization=disabled` + `unvirtualizedResources` (costs restricted-capability budget in an already-tight cert letter). Note: an alias-launched MCP exe runs *with* package identity and sees the widget's merged view — the statusline script is the reader that breaks. This answer also decides where the WS-C vault lives (MSIX uninstall deletes LocalCache — a virtualized vault would destroy the durable history it exists to preserve).

## Must-fix register (design changes before build)

1. **No raw account label in snapshot v1.** Labels are user-chosen and may be client names; the statusline render never needs one, and PRIVACY.md's whole posture forbids it in ambient files. For account-switch detection and delete-targeting, carry a short **label hash** (`account_ref`), not the label. MCP responses carry `scope: "active_account_only"` + `plan` + `account_ref`; the tool description tells the agent to have the user confirm the widget's active account when they run multiple. Revisit raw-label-opt-in when WS-D makes it load-bearing. *(Resolves the security-vs-correctness lens conflict: attribution honesty without the PII.)*
2. **Tenant-wall scoping on `get_local_burn_by_project`** — the most-corroborated finding (3 of 5 lenses). `CcLogReader` merges `~/.claude` + `~/.claude-personal` and keys by full cwd path; one innocent call from a work-seat session would inject personal-estate paths (client names, codenames, username) into an employer-visible transcript — and vice versa. Fix: results keyed **per root**, project **basenames** by default (`full_paths` param opt-in), scanned roots configurable, cross-home off by default, scoping rule stated in the tool description and manifest (`data_class: [local-fs-paths, cross-tenant-risk]`).
3. **Two tools + ping, not three.** `get_reset_schedule` is a strict field-subset of `get_usage` and creates a wrong-single-call path (agent sees "resets Fri 7p," never sees the 91%). Merge resets into `get_usage`. Add **`ping`** (server_version, schema_version, resolved snapshot path, snapshot_found, age_seconds, cc_roots_found) — the anchor step of every cold verify and the only way to distinguish server-broken from data-absent.
4. **Staleness as a structural discriminator, with shared constants.** Top-level `status: ok | stale | no_data` computed by the server at call time; thresholds as Core constants: fresh < 7.5 min (1.5× cadence), stale 7.5–15 min (data present, status forces acknowledgment), dead > 15 min (2 missed polls). `no_data` carries `reason` (`missing | malformed | disabled | widget_not_polling`) + a relayable `remedy` string. All failures are **typed tool results, never MCP protocol errors** (a protocol error reads as "server broken" and poisons the healthy tools). Server computes `age_seconds` and `resets_in_seconds` — never make the agent do clock math.
5. **Raw facts only in the snapshot.** `captured_at`, `schema_version`, `account_ref`, `plan`, `tiers[{key, utilization, resets_at, used/limit}]` — no precomputed pace or countdowns (they decay with wall clock; a baked verdict is wrong by read time). Readers must check `resets_at <= now` first and suppress crossed-tier utilization (`reset_crossed: true`, never the stale 88% two minutes after a reset — a fresh-by-age snapshot can be arbitrarily wrong at boundaries, and the five_hour tier crosses daily). Optional pre-rendered statusline string is acceptable (human-glance drift tolerable).
6. **Atomic write specified as mechanism, not vibe:** temp-file + `File.Replace`/`Move(overwrite)` same-volume, 2–3 retries, **logged** failures (never the repo's silent-swallow `File.WriteAllText` pattern — both existing write sites are the anti-pattern). Reader contract ships in both consumers: `FileShare.ReadWrite|Delete`, one retry, parse-failure = missing, never data. Atomicity is a *verification precondition*: it's what makes `MALFORMED_SNAPSHOT` always-a-bug instead of an unreproducible mid-write race.
7. **Failure-status writes.** On fetch failure the widget knows *why* (session expired / Cloudflare / network — it shows targeted UI) and the snapshot currently just ages. Write `status: error` + `error_kind` + `last_good` payload so "stale" becomes actionable ("wk 62% · reauth needed") instead of "is the widget running?" gaslighting.
8. **Registration durability + update-under-lock.** MSIX: **appExecutionAlias** (`uap3:Extension` on the existing Application node), never an absolute WindowsApps path (version-dies + ACL-blocked). Velopack: `current\` path (version-stable). Strongly consider the **shadow-copy thin launcher** (installed outside both package trees, copies the single-file exe to temp and execs): collapses both channels to one registration string AND solves update-under-lock — ~8 parallel CC sessions would otherwise pin the exe and stall Velopack swaps and Store servicing indefinitely. User-scope registration only, never project `.mcp.json` (machine paths in repo-committed files break teammates).
9. **Schema compat owned from day 1.** `schema_version` in the snapshot and every response; MCP ignores unknown additive fields, returns typed `snapshot_schema_unsupported` on major mismatch (a lenient stale-version parse returning silent 0% is how the "check quota before spawning" tool green-lights a fleet into a 94% week). Statusline script (a frozen artifact in the user's settings — no update channel) reads defensively, blanks + "update Sanduhr" on unknown major. WS-D's multi-account snapshot *adds* keys or a new file, never repurposes v1 fields.
10. **Lifecycle + uninstall teeth.** Toggle-off, account removal (when it's the snapshotted account), and last-account delete all **delete `snapshot.json`** (WS-A's `WebView2FetchDir` purge is the precedent); MCP treats missing as `no_data`, no cached last-known-good. Uninstall: in-app "Remove Claude Code integration" button; Velopack `OnUninstall` hook deregisters (the `VelopackApp` seam already exists in Program.cs); statusline script emits **empty output, never an error** when the snapshot's gone, so a dangling MSIX-orphaned entry degrades to invisible; MCP orphan cleanup documented (`claude mcp remove sanduhr`) + widget health-checks/repairs its registrations on start. Config writes: enumerate CC homes and **ask when more than one exists** (this machine's `~/.claude` is the employer seat — a silent default is a tenant breach), re-read before write, mutate only the owned key, temp+`File.Replace`, timestamped backup.
11. **Trust boundary by construction.** `sanduhr-mcp.exe` lives in a project that cannot reference `CredentialStore`/`WindowsCredentialManager` (reference only a snapshot-reader + CcLogReader slice) — makes the cert letter's "cannot touch credentials" claim structural. No tool ever accepts free-form paths/globs (params are enums + time windows) — the future-proofing against the exe becoming a file oracle. Manifest wording: "read-only by construction, verified by cold-agent pass," never "enforced."
12. **Ship-hygiene cluster:** sign both Velopack exes before this ships there (Smart App Control blocks unsigned regardless of launch path; EDR heuristics on "node spawns unknown unsigned exe reading ~/.claude" are a quarantine risk — SmartScreen itself is a non-issue for CreateProcess spawns). Rebudget the cert letter now (v3.1.0 letter is 1709/2000 chars; the second-exe paragraph must front-load: on-demand stdio child of the user's own CLI, no service, no autostart, no network listener, declared alias, removed on uninstall). PRIVACY.md ships in the same release: snapshot row + the honest MCP caveat (tool results become conversation content processed by Anthropic — "never transmitted anywhere" needs scoping). All snapshot timestamps UTC ISO-8601 with offset (`NowIso` precedent); readers render resets local; clamp negative ages.

## Agent-facing schema decisions (from the consumer lens)

- `get_usage` response: `status/reason/remedy`, `as_of` + `age_seconds`, `scope`, `account {ref, plan}`, `tiers[{key, label, utilization_pct, headroom_pct, resets_at, resets_in_seconds, pace {verdict, delta_pct}, projection {expires_before_reset, expires_in_seconds}, used?, limit?}]` — pace/projection **nullable** (routines has `resets_at: null` by design; "unknown" must be distinct from "none"), plus **`local_burn_since_snapshot`** `{total_tokens, by_tier, caveat}` via the existing `TokensSinceByTier(as_of)` — the staleness compensator for the double lag (endpoint minutes + poll cadence), labeled a token-count proxy, never fake-converted to a %.
- **Tool descriptions carry the behavioral trigger** or the feature never fires: "Call BEFORE spawning subagents, launching long autonomous runs, or choosing Opus vs Sonnet… stale or no_data means unknown headroom — never assume budget." Plus `readOnlyHint: true` annotations.
- A `can_i_afford(N tokens, model)` tool is **not honestly buildable in v1** — nobody has the tokens-per-utilization conversion. The honest path: after WS-C's vault accumulates local-delta vs observed-utilization windows, the correlation earns the estimate. Don't ship a guess.
- Statusline: **never blank on stale** — blank reads as "nothing to report" (absence of warning read as absence of problem, the human version of the exact agent failure this design forbids). Stale renders `sanduhr: stale 43m — start widget`; attach resets to their tier (`wk resets Fri 7p`); tier selection reuses existing settings, not hardcoded wk+opus. ~55 chars worst case, fits.

## Drift watchlist — affordances that must stay out

`switch_account` (mutates polling target + cookie swaps — credential-capture-adjacent, never prod-safe) · `refresh_now`/poll-trigger (read-only server becomes a command channel; claude.ai polling remotely triggerable) · anything touching Credential Manager (out of reach by project construction — keep it that way) · **MCP-side vault/rollup writes** (WS-C temptation: recreates the exact two-writer non-atomic hazard the brief warns about; vault writes stay widget-side, MCP reads rollups only after WS-C lands). Lifecycle rule: when WS-C/WS-D land — rescan, remap, reverify; every stamp resets.

## Verification plan (cold-agent, per the methodology)

Dev-tier env overrides `SANDUHR_SNAPSHOT_PATH` + `SANDUHR_CC_ROOTS` (read-redirection only, env-gated, never ship enabled) make the four `get_usage` states (fresh / never-ran / stale / malformed) and the CC-logs fixtures drivable from a manifest-only agent; `ping` anchors every run. **The full verify plan runs once per channel** — MSIX and Velopack differ in exactly the ways this review flagged. Draft `agent-access.json` skeleton (all affordances stamped `unverified`, including the snapshot file itself and `statusline.render` as first-class affordances) is in the panel output: `.superpowers/../scratchpad/mcp-review-*.md` (session artifacts); reproduce from this doc when building.

## Effort recalibration

Statusline Bridge was slated **S — it is realistically M** once the virtualization spike, lifecycle purges, failure-status writes, and the in-script reader contract are counted. Under-sizing it invites exactly the shortcuts (naive write, no lifecycle) this review exists to prevent. MCP server stays M.

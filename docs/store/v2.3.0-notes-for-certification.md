# Notes for certification — Sanduhr für Claude v2.3.0

Hello, and thanks in advance for the review.

This is **v2.3.0**, a feature update on top of the previously-certified
v2.2.0. No changes to the certified architecture: still a frameless
Win32-style desktop widget built on Qt 6 / PySide6, packaged via PyInstaller
into an MSIX with `runFullTrust` capability. No new sandbox-breaking
behavior, no kernel mode, no driver, no system services. Same publisher
identity, same `626LabsLLC.SanduhrfrClaude` package identity.

## What's new since v2.2.0

The visible additions:

1. **Daily Routines tier.** A new card alongside the existing weekly /
   session tiers. Pulls daily run-quota from
   `https://claude.ai/v1/code/routines/run-budget`. Same authentication
   path as the existing usage fetch — user's own session cookie,
   user-initiated.

2. **Local CC settings tab.** A new tab in the Settings dialog that
   reads token-usage events out of the user's own Claude Code session
   logs (located at `%USERPROFILE%\.claude\projects\` and
   `%USERPROFILE%\.claude-personal\projects\`). **Read-only, no upload,
   no modification, no network involvement.** The feature exists
   because Anthropic's `/usage` endpoint lags real consumption by
   several minutes; reading the local JSONLs gives a sharper "what just
   burned in the last 30 seconds" view. The tab is a Settings sub-page,
   not a foreground surface — users opt in by clicking the tab.

3. **Cards tab — drag-and-drop reorder.** The Settings dialog's "Pacing"
   tab is renamed "Cards" and its visible-tier list is now a drag-and-
   drop QListWidget. Users can reorder which tier cards show on the
   widget and uncheck ones they don't track. Pure UI change.

4. **Custom dialog sound chimes.** Replaces Windows system beeps on
   save / error / info / toggle confirmations with four short PCM-WAV
   tones (under 200 ms each, ~25% amplitude). Files lazy-built to
   `%APPDATA%\Sanduhr\sounds\` on first use, played asynchronously via
   `winsound.PlaySound`. No mic, no speaker exclusivity, no audio
   focus stealing.

5. **Win11 taskbar icon binding fix.** Frameless + always-on-top windows
   on Win11 had been dropping the small-icon variant for the taskbar
   button at first show. v2.3.0 forces an HWND recreation 150 ms after
   launch via Qt's `setWindowFlag` so the icon binds reliably. No
   undocumented APIs — uses `WS_EX_APPWINDOW` and `WM_SETICON` (both
   public Win32 documented since Windows 95).

The full developer-side changelog is at
[`windows/RELEASE_NOTES.md`](https://github.com/estevanhernandez-stack-ed/Sanduhr_f-r_Claude/blob/main/windows/RELEASE_NOTES.md)
and [`CHANGELOG.md`](https://github.com/estevanhernandez-stack-ed/Sanduhr_f-r_Claude/blob/main/CHANGELOG.md).

## Quick test path

1. **Install**, launch from Start Menu.
2. On first run, paste any string into the sessionKey field — the app
   will fail gracefully with "Session expired -- click Key" if the
   string isn't a real Claude session key. A real session key is
   obtained from the user's own browser at `claude.ai`
   (F12 → Application → Cookies); see the in-app Help tab for the
   exact path. We can't pre-provision a working test account because
   the session cookies are tied to the human account holder — the same
   constraint as the v2.2.0 review.
3. **Without a real session key**, the widget runs in a "preview" state
   showing one mock tier card plus a hint label. This is enough to
   verify the visual chrome, theme switching, drag, resize, taskbar
   icon, compact mode, deep-work focus timer, and snake game — none of
   which need network access.
4. **Settings → Cards** — drag a tier row up/down, uncheck a row, watch
   the widget update. New behavior, fully self-contained.
5. **Settings → Local CC** — if Claude Code isn't installed, the tab
   shows "No local CC activity in the last 30 days." with no errors.
   This confirms the soft-fail path for users without Claude Code.

## Capability re-justification

We continue to declare `<rescap:Capability Name="runFullTrust" />` for the
same reasons as v2.0–v2.2:

1. **Direct read/write to `%APPDATA%\Sanduhr\`** for settings, history,
   logs, and user-dropped theme JSONs. Users have asked for these to
   live at the real user path so they survive uninstall/reinstall and
   are easy to back up — not at a sandbox-virtualized per-package path.
2. **DWM ctypes calls for Mica backdrop**
   (`DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE, ...)`) — the
   Win11 native frosted-glass material. Sandboxed MSIX can't call DWM.

v2.3.0 adds one new full-trust use:

3. **Read-only access to `%USERPROFILE%\.claude*\projects\*.jsonl`** for
   the Local CC tab. These files are written by the user's own Claude
   Code installation; Sanduhr only reads them, never writes or
   modifies. The tab gracefully reports "no activity" when the
   directories don't exist.

No new network endpoints beyond `claude.ai` (already declared). No
telemetry. No analytics SDK. No advertising. No subprocess spawning. No
kernel hooks.

## What hasn't changed

- **Data collection: still none.** Sanduhr makes outbound requests only
  to `claude.ai` API endpoints, and only with the user's own session
  cookie. No usage telemetry to 626Labs servers.
- **Privacy policy:** unchanged from v2.2.0
  ([`docs/PRIVACY.md`](https://github.com/estevanhernandez-stack-ed/Sanduhr_f-r_Claude/blob/main/docs/PRIVACY.md)).
- **License:** MIT, source on GitHub at
  [`estevanhernandez-stack-ed/Sanduhr_f-r_Claude`](https://github.com/estevanhernandez-stack-ed/Sanduhr_f-r_Claude).
- **Trademark / branding:** "Sanduhr für Claude" — German for "hourglass
  for Claude." Not affiliated with Anthropic; positioned as a community
  third-party companion to the user's own Claude.ai subscription, same
  framing as the v2.0.2 listing copy that resolved the prior
  10.1.4.4 / "Content" finding.
- **Accessibility:** every chrome button has `setAccessibleName`,
  keyboard shortcuts visible in tooltips and the Help tab — same as
  v2.0.2's navigation remediation.
